## Corrections applied during implementation audit
- **External LRC is the authoritative lyric reference:** Embedded USLT/SYLT are treated only as existing MP3 metadata; the alignment source is always the external sidecar LRC.
- **Exact basename package contract:** Scanner matches MP3/LRC/JSON by basename and rejects missing sidecars; user-facing output contains exactly those three filenames in songs/final/.
- **Cumulative JSON:** The updater deep-merges only the phase2 namespace and verifies that all non-phase2 JSON data remains semantically identical.
- **Real CTC forced alignment:** MMS supplies frame-level emissions; reference tokens from the LRC are aligned by the standalone Viterbi CTC aligner with explicit repeated-label rules.
- **MMS Telugu adapter:** The model wrapper explicitly activates tokenizer language tel and model adapter tel.
- **LRC blank markers:** Blank markers are treated as high-priority lyric-free boundaries; no fake empty-transcript CTC chunk is created.
- **MP3 metadata preservation:** The final MP3 starts as a copy of the source and only the Phase-2-owned SYLT frame is modified; existing metadata is fingerprint-checked afterward.
- **Final JSON self-hash:** The JSON records a canonical self-excluding content hash; SQLite records the actual final JSON byte hash.
- **Force and resume:** Force clears the source-keyed checkpoint and DB child alignment state; normal restart reuses validated chunk artifacts.
- **Finished-song skip safety:** A song is skipped only when final MP3/LRC/JSON exist and the input identity, output hashes, JSON integrity, and non-phase2 preservation checks pass.
- **Chunk retries:** Chunk retry count is real and configurable; retries can increase context and use the original mix after the vocal stem result is poor.
- **Anchor validation:** Chunk results have a configurable LRC search window check and the final song computes aggregate anchor drift metrics.

## Verified invariants

- `songs/original/` is never an output destination.
- Original MP3/LRC/JSON hashes are rechecked after processing.
- Existing MP3 metadata is fingerprinted before and after embedding.
- Existing JSON content outside `phase2` is compared for equality.
- Final LRC and SYLT are generated from the same canonical word timeline.
- Final JSON stores provenance and quality metrics.
- DB stores actual final-file byte hashes; JSON uses the self-excluding canonical hash convention.

## Verification limitations

The build environment compiled the complete source and passed all local automated tests. The actual supplied sample package was smoke-tested for LRC parsing, JSON preservation, DB inventory, and real MP3 metadata-preserving SYLT embedding. The current build host does not have the full Transformers/Silero runtime installed and exposes no CUDA device, so a full Demucs + MMS + CTC five-minute sample run was intentionally not claimed.
